4.2 Idempotency 與失敗邊界

Phase 1依9/29責任分工：Python來源檢查配合單一站點DB transaction；座標範圍及act值域由INSERT時的CHECK驗證，任一列失敗則整批站點rollback，先前raw commit保留。其他既定驗證責任維持。相同鍵、相同標準化 source 欄位為 no-op；相同鍵不同 source 欄位為 conflict，整批 rollback。判定相同時不比較新執行的 run_id／ingested_at，也不能只用整份 body hash 判定單列。批內重複 station_id 一律拒絕，不偷偷選最後一列。

同 raw 重播只增加獨立的 attempt log，不增加有效 snapshot 或更新既有 lineage。下一次採樣即使 source_update_time 未改仍是新 observed_at。snapshot交易斷線／commit回應遺失時，先前已commit的raw保留，重播不得產生第二效果。raw交易本身失敗且確認未commit時，允許此次body遺失；若commit結果不明，不能假稱保存成功或失敗，須在DB恢復後依原身份查證再決定重播／重試，身份規則於raw DDL定案時補齊。這是兩個transaction的冪等恢復，不宣稱exactly-once。

Realtime endpoint 每次可能傳完整站點集合；「增量」指 append 新採樣歷史，不承諾來源支援只抓變動資料。Phase 1 先不實作自動 retry，失敗非零退出；Phase 2 加有限 retry。
